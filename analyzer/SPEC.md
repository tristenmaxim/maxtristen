# ТЗ: видео-анализатор на Gemini (без Whisper)

## Контекст

Часть личного набора инструментов на `maxtristen.com` (репо `github.com/tristenmaxim/maxtristen`,
разделы `/music/ /photo/ /downloader/`, паттерн: FastAPI backend + vanilla HTML/CSS/JS frontend,
тёмная дизайн-система — см. `photo/` в том репо как образец стиля и структуры).

Здесь — две связанные, но отдельные задачи, обе строятся на нативном понимании видео Gemini
(модель сама смотрит видео целиком — кадры, движение, звук), **без Whisper, без pyannote,
без ручного извлечения кадров/OCR**. Старые версии в `reference/` — это референс на то, ЧТО
инструмент должен уметь выдавать на выходе, а не код для переиспользования: пайплайн там был
инженерным обходом того, что старые модели (GPT-4o) не ели видео нативно. У Gemini этой проблемы
нет — она решается одним вызовом API с видеофайлом на входе.

## Задача 1 — Transcribe (приоритет)

**Референс:** `reference/transcribe-original.py` (970 строк, Whisper + pyannote diarization).
Смотреть только на то, ЧТО получалось на выходе: транскрипт с таймкодами и разбивкой по
спикерам ("Speaker 1: ...", "Speaker 2: ..." с меткой времени). Сам код Whisper/pyannote —
не трогать, не переиспользовать.

**Новая реализация:**
- Загрузить видео/аудио в Gemini напрямую (Files API), попросить транскрипт с таймкодами и
  диаризацией спикеров одним промптом — без отдельного шага транскрипции и отдельного шага
  диаризации, модель делает это за один проход
- Веб-обёртка (FastAPI, как `photo/backend/`): аплоад файла → асинхронная задача (обработка
  может занимать минуты на длинных видео) → poll-статус → готовый транскрипт. Паттерн
  poll-статуса уже есть в `downloader/backend/server.js` (`/progress/:id`) — тот же принцип,
  не изобретать заново
- Фронт: тёмная тема, токены из `photo/frontend/assets/styles.css` (`--bg #0c0e10`,
  `--accent #e8b84b` и т.д.) — тот же визуальный язык
- Путь в итоговом сайте: `/transcribe/`

## Задача 2 — TikTok Ads Analyzer (после задачи 1, на её базе)

**Референс:** `reference/tiktok-ads-analyzer-original.py`. Промпт там чистый, без проблем —
6 вопросов: что за продукт/сервис, структура и flow ролика, ключевые сообщения/тексты,
визуальные приёмы, целевая аудитория, маркетинговые/психологические приёмы. Эту структуру
вопросов можно взять как есть — это не про воспроизведение чего-то вредного, это обычный
разбор рекламного ролика.

**Новая реализация:** тот же Gemini-видео-инпут, тот же upload+poll каркас из задачи 1,
просто другой промпт (маркетинговый разбор вместо транскрипта) и, если есть аудио —
можно попросить Gemini учитывать транскрипт как часть того же запроса, отдельный проход
транскрибации не нужен.

## Что НЕ переносить, вообще

- `reference/video-analyzer-engine.py` (движок из "Crypto Rug-Pull Variation") — устарел
  целиком, решал проблему которой у Gemini нет (adaptive/text-aware извлечение кадров + OCR +
  сборка grid-картинки для GPT-4o vision). Не портировать архитектуру, не переиспользовать код.
  Если интересно посмотреть на историю — можно, но это не стартовая точка ни для чего.
- Промпты из этого же файла, если долистаете до методов `analyze_with_vision`/`summarize` —
  они были заточены под конкретное видео про мем-коины с легендой "я cybersecurity-исследователь",
  чтобы обойти отказ модели и получить пошаговую инструкцию воспроизведения rug-pull схемы.
  Не референс, не паттерн, не трогать.

## Общие технические заметки

- Ключи — только через `.env` на сервере (scp вручную), никогда в гит. См. `photo/backend/.env.example`
  в основном репо как образец.
- CI/CD уже настроен в основном репо (`maxtristen/.github/workflows/deploy.yml`) — деплой на
  push в main, systemd-юниты по образцу `deploy/maxtristen-photo.service`. Когда этот
  инструмент будет готов, его нужно будет влить в основной репо `maxtristen` как ещё один
  раздел (`transcribe/backend/` + `transcribe/frontend/`), не отдельным сайтом.
